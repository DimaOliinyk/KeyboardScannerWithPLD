# KeyboardScannerWithPLD
## Схема сканування матричної клавіатури для мікроконтролерів на основі PLD
### 1. Технологія PLD
Programmable logic device (PLD) – (програмований логічний пристрій) це
електронний компонент який використовується для створення схем, які можна
конфігурувати та змінювати користувачем. Цим пристроєм можна замінити
дискретні логічні елементи з фіксованими функціями.
Принцип роботи полягає у тому, що PLD складається з ряду логічних елементів,
ці логічні елементи приєднуються до матриці з’єднань до якої підключаються
входи, які являють собою буферні входи з інвертуючим та неінвертуючими
виходами. 

Приклад внутрішньої будови GAL 16V8 PLD:
<img width="1111" height="593" alt="image" src="https://github.com/user-attachments/assets/6f442335-10de-4a91-b79c-d3a3f3101149" />


Якщо у правильних точках матриці створити з’єднання, то можна утворити
функцію задану користувачем. Як матрицю з’єднань використовують елемент
пам’яті. У моделях PLD PAL (programmable array logic) використовувалась
одноразова пам’ять. У моделях PLD GAL (generic array logic) використовувалась
пам’ять EEPROM, що дозволяє перепрограмувати функцію кілька разів.
Наприклад, конфігурації «виключного або» створюється таким чином: Із таблиці
істинності впишемо функцію: 𝑌 = 𝐴 ∙ 𝐵̅ + 𝐴̅∙ 𝐵. Рядки у матриці працюють як
послідовне з’єднання і відповідають логічному «і», а всі рядки під’єднуються до
логічного «або». Таким чином в одному рядку створимо з’єднання A та 𝐵̅, а в
іншому А̅ та B. І з’єднавши з логічним «або» отримуємо потрібну функцію.

### 2. Схема сканування клавіатури
Синтез схеми створювався з метою зменшення задіяних пінів мікроконтролерів.
Сканування матричної клавіатури мікроконтролером без додаткових схем
вимагає кількість пінів рівну сумі клавіш по колонках і рядках. Кінцева схема
використовуватиме один вхід для обрання однієї клавіші, а вихід буде
відображати стан цієї кнопки.
Для перемикання по одному рядку матричної клавіатури використовується
дешифратор. Завдяки йому можна подавати сигнал на окремий рядок окремо.
Потім кожна колонка під’єднується до входів мультиплексора із резисторами, які
підтягують до землі. Таким чином натискання клавіші утворює перетин рядків і
стовпців, що потім відображається на виході мультиплексора.
Поточна схема використовуватиме 4 входи керування для задання кодів для
декодера та мультиплексора. Однак двійкові коди, які подаються на схеми є
послідовними, тому їх можна подавати лічильником. Як лічильник було обрано
послідовний синхронний КР1533ИЕ5. Для керування лічильниками потрібно два
входи – для тактового сигналу та для скидання лічильника (оскільки реальні
лічильники починають у невизначеному стані при запуску).
Кінцева схема використовує лише 3 порти мікроконтролера – подача такту,
скидання лічильника (використовуються один раз при ввімкненні), та вихід
мультиплексора, який передає стан поточної кнопки.
У даній схемі використовується матрична клавіатура 3x3, а кількість клавіш які
перевірятимуться – 16. Тому програмно пропускається 4та кнопка кожного рядка
та 4 кнопки останнього рядка. 

Принципова схема побудована в LTSpice:
<img width="815" height="560" alt="image" src="https://github.com/user-attachments/assets/295f64a3-9c88-4238-9ff0-7e4796ed1dca" />

Запрограмуємо мультиплексор та дешифратор у PLD GAL22V10D. Для
програмування використовується застосунок [WinCupl](https://www.microchip.com/en-us/products/fpgas-and-plds/spld-cplds/pld-designresources).

Запишемо формули функцій:
- Дешифратора:
  
$Y_0 = \overline{X_1} \cdot \overline{X_0}$

$Y_1 = \overline{X_1} \cdot X_0$

$Y_2 = X_1 \cdot \overline{X_0}$

$Y_3 = X_1 \cdot X_0$


- Мультиплексора (A, B, C, D – вхідні значення, X3, X2 – керуючі):
$Y_{out} = A \cdot \overline{X_3} \cdot \overline{X_2} + B \cdot \overline{X_3} \cdot X_2 + C \cdot \overline{X_2} \cdot X_3 + D \cdot X_3 \cdot X_2$

Для програмування функцій потрібно спершу оголосити порти, які
використовуються, та присвоїти їм імена. Потім записуються вирази функцій:
```
/* *************** INPUT PINS DCD *********************/
PIN 1=X0; /* Decoder input switches between */
PIN 2=X1; /* 4 pins connected to 4 columns */

/* *************** INPUT PINS MULT *********************/
PIN 3=X2; /* Multeplexes controlling pins to */
PIN 4=X3; /* switch between 4 inputs */
PIN 5=A; /* Input signal 1 connect to row 1 */
PIN 6=B; /* Input signal 2 connect to row 2 */
PIN 7=C; /* Input signal 3 connect to row 3 */
PIN 8=D; /* Input signal 4 connect to row 4 */

/* *************** OUTPUT PINS DCD *********************/
PIN 23=Y0; /* Column 1 */
PIN 22=Y1; /* Column 2 */
PIN 21=Y2; /* Column 3 */
PIN 20=Y3; /* Column 4 */

/* *************** OUTPUT PINS MULT *********************/
PIN 19=Yout;     /* Output of the multiplexer (main output) */

/* DCD Logic */
Y0 = !X1 & !X0;
Y1 = !X1 & X0;
Y2 = X1 & !X0;
Y3 = X1 & X0;

/* MULT Logic */
Yout = A & !X3 & !X2 #
B & !X3 & X2 #
C & X3 & !X2 #
D & X3 & X2;
```

> [!TIP]
> Після написання коду треба використати програматор, для записування
> потрібних перетинів у матриці пам’яті для утворення функцій. Програматор
> потребує особливий файл. Щоб його отримати, потрібно на панелі інструментів
> у WinCupl натиснути кнопку Device Dependent Compile, після успішної
> компіляції, у файловому провіднику з’явиться файл з розширенням .jed. Потім у
> будь-який програматор, який підтримує обраний PLD, можна завантажити цей
> файл і запрограмувати PLD.

Алгоритм контролера заключатиметься у надсиланні імпульсу на скидання
лічильника при запуску, потім надсилання імпульсів і збереження їх кількостей,
потім перевірятиметься вхід від PLD. Якщо клавіша замкнута, то мікроконтролер виводитиме записані символи записані у масив (який виступає словником). За
мікроконтролер було обрано Arduino (Pro) Micro, оскільки він може
представлятись клавіатурою комп’ютеру. 
Також алгоритм зобов’язаний враховувати те що зібрана схема має матрицю
клавіш 3х3, а не 4х4 на яку розрахована схема PLD.

```
class StreamDeck
{
public:
  StreamDeck(uint8_t clockPin, uint8_t resetPin, uint8_t readPin, uint8_t
    pulseTime = 5, bool pulseVal = 1)
  {
    _clockPin = clockPin;
    _resetPin = resetPin;
    _readPin = readPin;
    _pulseTime = pulseTime;
    _pulseVal = pulseVal;
  }

  void begin()
  {
    pinMode(_clockPin, OUTPUT);
    pinMode(_resetPin, OUTPUT);
    pinMode(_readPin, INPUT);
    Reset();
  }

  void Reset()
  {
    _SendPulse(_resetPin);
  }

  void SendPulse()
  {
    _SendPulse(_clockPin);
  }

  void SkipPulses(uint8_t count)
  {
    for(int i = 0; i < count; i++)
      SendPulse();
  }

  bool ReadPin()
  {
    return digitalRead(_readPin);
  }

  // Замість рядків з цифрами можна впсати будь-які бажані символи
  String dictionary[9] = {
    "1", "4", "7",
    "2", "5", "8",
    "3", "6", "9",
  };

private:
  uint8_t _clockPin;
  uint8_t _resetPin;
  uint8_t _readPin;
  uint8_t _pulseTime;
  bool _pulseVal;

  void _SendPulse(uint8_t pin)
  {
    digitalWrite(pin, _pulseVal);
    delay(_pulseTime);
    digitalWrite(pin, !_pulseVal);
  }
};

uint8_t row = 0;
uint8_t col = 0;
uint8_t keyNum = 0;
volatile uint16_t bitArr = 0;
StreamDeck strDeck(7, 5, 2);

void setup()
{
  Serial.begin(9600);
  strDeck.begin(); // Скидаємо лічильник
  Keyboard.begin();
}

void loop()
{
  if(strDeck.ReadPin()) // Зчитуємо значення з урахуванням брязкіту
  {
    delay(1);
    if(strDeck.ReadPin())
    {
      Keyboard.print(strDeck.dictionary[keyNum]);
      delay(45);
    }
  }

  keyNum++; // Рахуємо наступний імпульс пропускаючи 4 ряд, 4 стовп
  if(!(keyNum % 3))
  {
    strDeck.SkipPulses(1);
  }

  if(keyNum == 9)
  {
    keyNum = 0;
    strDeck.SkipPulses(4);
  }

  strDeck.SendPulse();
  delay(1);
}
```

## Висновок 
PLD надають можливість створювати логічні схеми і виконувати дебагінг прямо
на місці. Оскільки всі логічні схеми складаються в одному компоненті, то
зменшується кількість фізичних з’єднань за які має пам’ятати інженер, таким
чином перешкоджаючи можливість створення помилки під час з’єднання
компонентів.
Схема сканування клавіатури зменшує кількість пінів мікроконтролера, які
будуть задіяні у його роботі, збільшуючи кількість вільних пінів і розширюючи
його можливості.
Матричне сканування має лінійну залежність складності, оскільки час який
витрачається на сканування всіх клавіш пропорційна їх кількості. Для
надолуження можна було б використати паралельний лічильник, щоб зменшити
час обчислення. Однак для сканування великої кількості клавіш ефективніше
використати аналогову клавіатуру, де час сканування залежить від часу
перетворення з аналогового в цифровий сигнал АЦП.
